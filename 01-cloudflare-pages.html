Cloudflare Pages 构建配置 · 详细步骤

轻页 PDF 工具 · qingye-pdf-tools · 你已完成「Connect to Git」，接下来是构建配置这一步

先说结论：这四项照抄，不要改。

框架预设选 None，构建命令 python3 build.py --build，构建输出目录 dist，根目录留空。填完点「保存并部署」。

你现在在哪一步

你已完成仓库连接（Connect to Git）。Cloudflare 接下来会让你配置「构建设置」。这一页字段多、容易误填，我逐个说清每个字段填什么、以及填错会出现什么现象。

配置字段逐项对照

界面字段填什么为什么
项目名称
Project name		 qingye-pdf-tools 只影响 Cloudflare 上的项目名和默认域名 xxx.pages.dev，随时可改。
生产分支
Production branch		 main 只有往这个分支推送才触发自动部署。选错的话 push 后没有任何反应。
框架预设
Framework preset		 None 本站是纯静态 HTML，不走任何框架的构建流程。选错会触发它自己的构建脚本，覆盖你的配置。
构建命令
Build command		 python3 build.py --build 关键。--build 让脚本把产物输出到 dist/（不加则输出到 site/，与你要填的输出目录不匹配，构建会报「找不到目录」）。
构建输出目录
Build output directory		 dist 关键。必须是 dist，不要写成 ./dist、dist/ 或 site。这个字段要和 build.py 实际输出的目录名完全一致。
根目录
Root directory		 留空
（不填，默认为仓库根）		 留空表示 build.py 在仓库根目录。如果填 qingye-pdf-tools 之类的子目录，脚本就找不到了。
环境变量
Environment variables		 不用加 域名已经写在仓库里的 domain.txt，构建时脚本自己读，不需要在 Cloudflare 上配。

最容易踩的两个坑

1. 构建命令漏了 --build。这时脚本输出到 site/，而输出目录填的是 dist，Cloudflare 会报「输出目录不存在」或部署出一个空站。--build 是开关，不能省。

2. 输出目录填成 ./dist 或加了斜杠。Cloudflare 认的是相对仓库根的路径，写法要干净。就填三个字母加两个字母：dist。

操作步骤

1

在「构建设置」页面找到框架预设下拉框，选 None。

选 None 后，下方才会出现「构建命令」「构建输出目录」这两个可填字段。有些界面在选 None 之前它们是灰的。

2

构建命令框里输入（注意有空格）：

python3 build.py --build

不要写成 python build.py（少了 3 可能找不到）、./build.py（不可执行）、或 python3 build.py（漏了 --build）。

3

构建输出目录框里输入：

dist
4

根目录保持空白，不要填任何东西。

如果界面默认填了 / 或仓库名，保持原样即可，/ 等价于仓库根。

5

生产分支确认为 main。

你的仓库主分支就是 main（本地 git branch --show-current 验证过）。

6

点「保存并部署」（Save and Deploy）。

首次部署通常 1-3 分钟，因为要拉 21MB 的依赖并构建。之后每次 push 约 30 秒。

怎么确认成功了

部署完成后，Cloudflare 会给你一个 https://qingye-pdf-tools.pages.dev（或类似名字）地址。先用它验证，成功后再绑域名。

  1. 打开该地址，页面能正常显示，27 个工具卡片都在
  2. 随便点一个工具（比如「合并 PDF」），拖个文件进去，能出结果
  3. 重点：试一次 OCR。它是唯一依赖 8MB 外部资源的工具，最容易暴露问题

为什么 OCR 最值得优先测

OCR 要加载 wasm 内核和语言模型，浏览器用 importScripts() 加载内核时会检查响应的 MIME 类型。Cloudflare 对 .wasm.js 默认给的类型可能不对，浏览器会直接拒绝 —— 表现为「核心组件加载失败」。

我在 _headers 里已经指定了 Content-Type: application/javascript 绕开这个问题，但只有在 Cloudflare 上真跑过才能确认生效。

想看资源有没有正常加载，打开浏览器开发者工具的 Network 面板，找这几个请求，它们应当全部 200：

/vendor/ocr/tesseract.esm.min.js
/vendor/ocr/worker.min.js
/vendor/ocr/tesseract-core-*.wasm.js
/vendor/ocr/chi_sim.traineddata.gz
/vendor/ocr/eng.traineddata.gz

如果看到 Content-Type: text/html（而不是 JavaScript），说明 _headers 没生效，需要检查 dist/_headers 是否真的被发布了。

构建失败了怎么办

点进失败的那次部署，看构建日志（Build log）。常见几种：

日志里出现原因与处理
Directory not found
或找不到 dist		 构建命令漏了 --build，产物去了 site/。补上即可。
ModuleNotFoundError 不会有这个问题 —— build.py 只用 Python 标准库，不装任何第三方包。
构建成功但页面 404 输出目录名和实际产物目录不一致。确认是 dist 而不是 site。
找不到 vendor/ocr 资源 产物缺 OCR 资源。构建日志里应该会出现「vendor/ocr/ 为空」的提示 —— 这是我故意加的校验，出现就说明 vendor/ 没被提交进仓库，检查 .gitignore。
构建成功但改了代码没生效 推的不是 main 分支。Pages 只对生产分支触发部署。

接下来：绑定 pdf.linwt.top

验证 pages.dev 地址正常后，再绑自定义域名（避免域名指向空站时排查困难）。

  1. Pages 项目 → Custom domains（自定义域）
  2. 点 Set up a custom domain
  3. 输入 pdf.linwt.top，回车
  4. Cloudflare 会自动添加 DNS 记录。如果它要求你手动加，填：类型 CNAME、名称 pdf、目标 qingye-pdf-tools.pages.dev
  5. 等待证书签发，通常几分钟到半小时

之后每次上线就走这一条命令：

cd /Volumes/2t/workplace/网站副业pdf
./deploy.sh "这次改了什么"

脚本会先本地构建校验（和云端跑同一个 build.py --build），通过后提交并推送，约 30 秒后线上自动更新。

想撤销：git revert HEAD --no-edit && git push origin main

两个入口会同时在线：pdf.linwt.top（Cloudflare，主入口）与 qingye-pdf-tools.app.workbuddy.host（保留）。sitemap.xml 与 robots.txt 里两者都已声明。
